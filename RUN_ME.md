# RUN_ME.md — развёртывание `zohar-translator` на машине оператора

> _Документ составлен Claude с учётом его рантайма; LLM-агенты других
> семейств — адаптируйте детали к своим возможностям, сохраняя смысл._
>
> **LLM-агент, читающий этот файл:** оператор может иметь минимальный
> технический опыт. Действия, которые ты способна выполнить сама в рамках
> текущих разрешений — выполняй.

## Что это

Один раз, при первом развёртывании. После прохождения 8 стадий у оператора
на машине стоит работающий `zohar-translator` — GUI + Telegram-бот для
длинного LLM-перевода выбранного корпуса. Затем он запускается обычным
образом (`python src/gui.pyw`) и `RUN_ME.md` больше не нужен.

`RUN_ME.md` — driver для тебя, LLM-агента. Ты ведёшь оператора через
адаптацию под его корпус: язык, источник, структура текста, словарь,
стиль перевода, площадка публикации. Решения оператора и твой прогресс
ты сохраняешь в `progress.json` и `project.config` — чтобы новая
LLM-сессия (если эта прервётся) могла подхватить с того же места.

## Prerequisite

Единственное, что оператор делает руками **до** запуска тебя:
устанавливает Claude Code (или аналогичный LLM-агент с инструментами)
и оплачивает действующую подписку Claude Pro / Max. Дальше всё ведёшь
ты по этому файлу.

Версия Python ≥ 3.11. Если её нет — установишь сама на стадии 1.

## Принципы взаимодействия

**Главный принцип.** Для оператора, который уже решил пройти процесс,
всё должно быть бесшовно. Если это его первый контакт с LLM-агентом и
с GitHub — он должен интуитивно справиться, а не застрять. Не
предполагай технического опыта; не вываливай команды без объяснения.

**Градация действий — что делать самой, что согласовывать.**

| Тип действия | Поведение |
|---|---|
| Локальные read-only (читать файл, проверить версию python, посмотреть структуру каталога, дёрнуть `glossary_tool.py` запросом) | Делай молча. |
| Локальные write без побочных эффектов (создать пустую папку, скопировать шаблон, `pip install -r requirements.txt`) | Делай, кратко сообщай результат. |
| Долгие сетевые операции (скачать корпус через `download_sefaria.py` — часы трафика; первый `git push`) | Объясни что собираешься, оцени время, спроси «начинаем?» одной кнопкой. |
| Деструктивные (удалить `state/`, перезаписать непустой файл, kill процесса) | Всегда явное подтверждение оператора. |
| Секреты (`TG_BOT_TOKEN`, `GH_TOKEN`) | Пошагово ведёшь оператора к их получению (BotFather, GitHub Settings → Developer settings). Принимаешь значение, вставляешь в `.env` сама. **Никогда не выводишь в чат и не логируешь.** |
| Контентные решения (что считать «статьёй» в корпусе, какие термины класть в словарь, стиль перевода, целевые языки) | Всегда у оператора. Объясняешь варианты, показываешь последствия, ждёшь выбор. |

**Q-A протокол.** Вопросы оператору — по одному. Формат `(Q N из NN: …)`,
где NN — известное число вопросов в текущей стадии (если знаешь
заранее) или просто `…` (если поток уточняющий). Не группируй
несколько вопросов в одно сообщение «можно ответить подряд» —
оператор воспринимает это как обход правила «по одному».

**Когда не уверена.** Лучше задай уточняющий вопрос, чем сделай
догадку, влияющую на дальнейшие стадии. Архитектурные решения
(структура корпуса, словарь) дороже всего откатывать.

## Файлы прогресса

Ты ведёшь два файла в корне репо. Оба создаются на стадии 1 из
шаблонов `progress.json.template` / `project.config.template`.

**`progress.json`** — твой собственный журнал. Минимум:

```json
{
  "current_stage": 3,
  "completed_stages": [1, 2],
  "answers": {
    "stage1.python_version": "3.12.4",
    "stage2.source_kind": "sefaria_fast_path",
    "stage2.source_url": "https://www.sefaria.org/...",
    "stage3.chunk_unit": "article"
  },
  "notes": []
}
```

Каждый ответ оператора, влияющий на дальнейшие стадии, сохраняй в
`answers` с ключом `stageN.<short_name>`. После каждой стадии —
дописывай её номер в `completed_stages` и обновляй `current_stage`.

**`project.config`** — постоянные параметры адаптации корпуса (то,
что нужно и тебе, и работающему рантайму). Минимум: `HEB_ROOT`
(корень корпуса на диске оператора), `CORPUS_NAME`, `SOURCE_LANG`,
`TARGET_LANG`, `GH_REPO` (целевой репо публикации), `LANDING_LANGS`.
Формат — `.env`-совместимый, чтобы `src/config.py` мог его
прочитать как обычный `.env`.

**Если сессия прерывается.** Новая LLM-сессия читает `progress.json`,
видит `current_stage`, открывает соответствующий `stages/NN_*.md` и
продолжает с того же места. `answers` гарантируют, что повторных
вопросов не будет.

## Стадии адаптации

Каждая стадия — отдельный документ под `stages/`. Открывай и читай
**только текущую** (ленивая подгрузка — экономит контекст). Между
стадиями обновляй `progress.json`.

1. [`stages/01_setup.md`](stages/01_setup.md) — **Environment.** Python,
   зависимости, проверка что стоковый `gui.pyw` стартует. Создание
   `progress.json` / `project.config` из шаблонов.
2. [`stages/02_source.md`](stages/02_source.md) — **Source loader.**
   Что и откуда грузим. Fast-path: Sefaria через
   [`reference/source_loader/download_sefaria.py`](reference/source_loader/download_sefaria.py).
   Иначе — пишем свой loader по образцу.
3. [`stages/03_text_structure.md`](stages/03_text_structure.md) —
   **Text structure.** Единицы чанкования (главы → статьи →
   параграфы или своя иерархия). Опирается на
   [`reference/source_loader/CATALOG_STRUCTURE.md`](reference/source_loader/CATALOG_STRUCTURE.md).
4. [`stages/04_glossary.md`](stages/04_glossary.md) — **Glossary.**
   Взять наш `glossary/glossary.json` как эталон, адаптировать
   структуру, или собрать с нуля. Доступ через
   [`corpus_tools/glossary_tool.py`](corpus_tools/glossary_tool.py) —
   переводчик-агент **не загружает** словарь целиком, ходит
   запросами.
5. [`stages/05_prompt.md`](stages/05_prompt.md) — **Prompt template.**
   Стиль перевода, сноски, «творческие» места. Базис —
   [`templates/translation_prompt.md`](templates/translation_prompt.md);
   подставляются `{{HEB_ROOT}}`, `{{CORPUS_TOOLS}}` и т.п.
6. [`stages/06_publish.md`](stages/06_publish.md) — **Publish target.**
   GitHub Pages по нашему шаблону / другой таргет / без онлайна.
   Сюда же — `GH_TOKEN`, primary GH Pages, лэндинг на 11 локалях.
7. [`stages/07_smoke.md`](stages/07_smoke.md) — **Smoke run.** Короткий
   прогон через адаптированную GUI+TG-систему на синтетическом
   корпусе. Self-contained fixture внутри `tests/` или `examples/`.
8. [`stages/08_handoff.md`](stages/08_handoff.md) — **Hand-off.** Ты
   передаёшь работающую систему оператору; он запускает GUI на полном
   корпусе и мониторит через TG-бота.

## Hand-off (после стадии 8)

После последней стадии твоя работа закончена. У оператора:

- Адаптированный `zohar-translator` в локальной папке.
- Заполненный `.env` (с реальными секретами — у него на диске; в репо
  не закоммичены, защищены `.gitignore`).
- `progress.json` со статусом `current_stage: "done"`.
- Прошедший smoke-test pipeline.

Оператор запускает `python src/gui.pyw`, выбирает корпус, нажимает
**Старт**. Перевод длинного корпуса (часы–недели реального времени)
идёт без участия LLM-агента развёртывания: orchestrator сам спавнит
translator-субпроцессы через `claude.exe -p`, переживает 5-часовые и
недельные лимиты подписки, делает resume через `partial_state`,
коммитит результат на GitHub Pages.

Архитектурные детали — в [`ARCHITECTURE.md`](ARCHITECTURE.md).
Подробности устройства каталога корпуса — в
[`reference/source_loader/CATALOG_STRUCTURE.md`](reference/source_loader/CATALOG_STRUCTURE.md).
