# Стадия 4 — Glossary

**Цель.** У переводчика-агента есть инструмент `glossary_tool.py`, через
который он ищет/добавляет термины во время перевода. Сам словарь
лежит в `glossary/glossary.json` — он **не загружается в промпт**,
доступ только запросами.

## 4.1 Ключевой инвариант — почему так

Длинный корпус → словарь растёт до тысяч записей. Если грузить
его целиком в каждый вызов translator-агента — съест половину
контекста и денег. Поэтому архитектура такая:

- Словарь лежит файлом на диске.
- Translator знает о его существовании из своего промпта
  (`templates/translation_prompt.md`).
- Когда встречает новый термин — вызывает
  `python corpus_tools/glossary_tool.py find <term>`.
- Когда фиксирует перевод нового термина — `... add <term> <ru>`.
- Между вызовами файл сериализуется на диск; конкурентный доступ
  не предусмотрен (orchestrator сериализует translator'ов через
  batch-механику).

Этот инвариант — обязательный для всех корпусов. Меняется только
**структура полей** в `glossary.json` (под язык, под предметную
область).

## 4.2 Развилка по содержимому

**(Q 1 из 1: какой стартовый набор словаря?)**

- **(α) Тот же корпус (Зоар на русский).** Бери наш
  `glossary/glossary.json` целиком как стартовую точку. >300 правил,
  иврит/арамит/гершаимы → русский, выверены за месяцы перевода. Дальше
  оператор будет дополнять под свой стиль.
- **(β) Другой корпус, иврит/арамит → русский.** Бери структуру нашего
  файла, заполнение начинай с нуля (термины Зоара не подойдут к
  Талмуду или Танаху). Можешь оставить наш список как `reference/`
  для подсматривания.
- **(γ) Другой язык-источник или язык-цель** (например, рус → англ,
  греческий → русский). Структура нашего файла заточена под
  иврит-специфику (`he`, `nikud`, `gershayim_form`). Перепиши схему
  под свои потребности: поля для исходного термина, варианта(ов)
  перевода, примечаний, может быть POS-тэга. Сохрани верхнеуровневую
  идею «массив объектов с уникальным id» — `glossary_tool.py` от
  неё зависит.

## 4.3 Структура нашего файла (для (α) и (β))

Каждая запись — объект с ключами (округлённо, точное — открой
`glossary/glossary.json` сама):

- `id` — уникальный, обычно транслитерация термина.
- `he` — иврит/арамит как в источнике.
- `nikud` — с огласовками (для редких слов).
- `gershayim_form` — форма с гершаимами (для аббревиатур).
- `ru` — основной русский эквивалент.
- `ru_alt` — допустимые варианты.
- `notes` — комментарий переводчика (когда выбирать какой вариант).
- `tags` — категории (имена, понятия, формулы).

`glossary_tool.py` поддерживает: `find <query>`, `add ...`, `list`,
`export`. Команды и формат — в
[`templates/glossary_tool_guide.md`](../templates/glossary_tool_guide.md).

## 4.4 Адаптация под путь (γ)

Если оператор взял другой языковой паттерн — нужно править оба:

- `glossary/glossary.json` — новая схема (твоя).
- `corpus_tools/glossary_tool.py` — поля под find и add подкрутить
  под новые ключи. Это python с минимальной логикой (~200 строк),
  оператора не пугать; ты сама правишь и тестируешь:

  ```
  python corpus_tools/glossary_tool.py find <тестовый-термин>
  ```

Не ломай контракт «один JSON-файл, читается/пишется атомарно». Не
переходи на SQLite/Postgres — лишняя зависимость для оператора.

## 4.5 Адаптация `glossary_tool_guide.md`

Если ты меняла структуру (путь (γ)) — обнови шапку
`templates/glossary_tool_guide.md`: примеры команд должны
соответствовать новым полям. Translator-агент будет читать этот гайд
как часть промпта (см. стадию 5).

## 4.6 Запись прогресса

```json
{
  "current_stage": 5,
  "completed_stages": [1, 2, 3, 4],
  "answers": {
    ...,
    "stage4.glossary_strategy": "alpha_zohar_inherited",
    "stage4.glossary_entries_initial": 312,
    "stage4.schema_modified": false
  }
}
```

## Чек-лист стадии 4

- [ ] `glossary/glossary.json` существует в репо, валидный JSON.
- [ ] `python corpus_tools/glossary_tool.py find <любой-термин>`
      работает (отдаёт результат или пустоту, не падает).
- [ ] Если меняла структуру — `glossary_tool.py` обновлён,
      `glossary_tool_guide.md` отражает новые команды.
- [ ] Оператор понимает: словарь растёт по ходу перевода
      translator-агентом, ручная правка не обязательна.
