# Стадия 5 — Prompt template

**Цель.** В `templates/translation_prompt.md` лежит промпт, который
получает каждый translator-агент при старте. Он адаптирован под
конкретный корпус: язык, стиль, правила оформления, доступ к словарю,
сноски.

## 5.1 Что внутри стокового промпта

Открой [`templates/translation_prompt.md`](../templates/translation_prompt.md)
и прочитай целиком — это твоя стартовая точка. Структура:

- **Роль и контекст:** «ты переводишь N-й чанк статьи такой-то из
  такого-то корпуса с такого языка на такой».
- **Стиль перевода:** буквальный / литературный / смешанный; правила
  для «творческих» мест (где приходится отступать от буквы).
- **Правила оформления:** ссылка на
  [`templates/formatting_rules.md`](../templates/formatting_rules.md)
  (тире vs дефис, кавычки, сноски, нумерация).
- **Доступ к словарю:** инструкция вызывать
  `python {{CORPUS_TOOLS}}/glossary_tool.py find <term>` для новых
  слов, `add` для фиксации перевода. Гайд —
  [`glossary_tool_guide.md`](../templates/glossary_tool_guide.md).
- **Сноски:** где и как помечать места, требующие комментария
  переводчика-человека.
- **Подстановки `{{HEB_ROOT}}`, `{{CORPUS_TOOLS}}`, `{{GLOSSARY_PATH}}`** —
  заполняются автоматически в
  [`corpus_tools/build_batch.py`](../corpus_tools/build_batch.py)
  перед запуском translator'а; в файле остаются как литералы.

## 5.2 Что нужно спросить у оператора

**(Q 1 из 3: пара языков?)** Источник и цель. У стокового — иврит/арамит
→ русский. Возможны: рус → англ, греческий → русский, латынь → испанский,
англ → китайский и т.д. Влияет на инструкции по транслитерации,
порядку слов, идиоматике.

**(Q 2 из 3: стиль перевода?)**

- **Буквальный** (близко к источнику, синтаксис исходника
  просвечивает) — для священных и юридических текстов.
- **Литературный** (читается как родной) — для прозы, поэзии,
  философии.
- **Смешанный** (буквально, но с правками синтаксиса под
  читабельность) — наш дефолт для Зоара.

**(Q 3 из 3: сноски на «творческие» места?)** Если перевод где-то
сильно отступает от буквы — translator может пометить такие места
сноской `*N` с пояснением «здесь буквально было X, переведено как Y
ради Z». На сайте сноски рендерятся отдельным блоком. Нужно? — вопрос
к оператору, не к тебе.

## 5.3 Адаптация файла

Открой `templates/translation_prompt.md` под редактирование. Замени:

- **Шапку с описанием корпуса** — на свой корпус (название,
  историческая эпоха, специфика, ссылки на источник). 1-2 абзаца,
  никакой воды.
- **Языковую пару** — везде, где упомянуты «иврит», «арамит»,
  «русский» — на актуальные языки.
- **Блок про стиль** — выбери и распиши выбранный вариант. Удали
  два невыбранных, чтобы не путать translator-агента.
- **Правила транслитерации** — если применимо (например, для имён
  собственных греческого → русского нужны правила).

`formatting_rules.md` правь только если нужны другие пунктуационные
конвенции (например, китайский требует своих кавычек). Минорно.

## 5.4 Проверка подстановок

`build_batch.py` подставляет:

| Плейсхолдер | Чем заменяется |
|---|---|
| `{{HEB_ROOT}}` | значение из `project.config` |
| `{{CORPUS_TOOLS}}` | абсолютный путь к `<repo>/corpus_tools/` |
| `{{GLOSSARY_PATH}}` | `<repo>/glossary/glossary.json` |
| `{{ARTICLE_ID}}`, `{{CHUNK_NUM}}` | конкретные значения per batch |

Если ты добавила новые плейсхолдеры в промпт — допиши их в
substitution-dict в `build_batch.py` (одна строка). Это нормально,
проект для того и устроен.

## 5.5 Сухой запуск промпта (опционально)

Перед smoke-test'ом (стадия 7) полезно прогнать промпт на одном
чанке вручную. Возьми любую статью из `articles_catalog.json`,
сгенерируй промпт через `build_batch.py --dry-run` (если такой режим
есть; иначе посмотри что генерится в `.batch/` после стартового
прогона) и прочитай: понятно ли translator-агенту что делать?
Не противоречит ли сам себе?

Если что-то режет глаз — правь сразу, не доноси до стадии 7. На
этой стадии итерация дешевле.

```json
    "stage5.style": "смешанный",
    "stage5.footnotes_enabled": true,
    "stage5.prompt_revision": "v1"
  }
}
```
