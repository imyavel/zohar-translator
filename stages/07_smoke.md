# Стадия 7 — Smoke run

**Цель.** Адаптированный pipeline за минуты прогоняет короткий
синтетический корпус end-to-end: source → catalog → translator → results
→ build_site → (deploy). Если падает — фиксим прямо здесь, **не** на
полном корпусе оператора.

Это стадия, которую LLM-агент (ты) **планирует и осуществляет
самостоятельно**. Оператора не загружай — только итог: «прошло /
не прошло, вот лог».

## 7.1 Self-contained fixture

Под `examples/smoke/` собери минимальный набор:

- 3-5 коротких статей (по 500-2000 символов каждая) в формате
  адаптированного source loader'а. Содержимое — литературно
  адекватное, на исходном языке корпуса. Допустимо взять public
  domain отрывок из Википедии / Гутенберг проекта по теме.
- Соответствующий `examples/smoke/Source/catalog.json` (хэндкрафт).
- 1 чанк предопределённого reference-перевода для сравнения
  («ожидаемый результат»). Не строгое сравнение — translator всё
  равно даёт небайтоидентичные тексты — но смысловая близость
  валидируема.

Если такого набора нет в репо — собери и закоммить как часть стадии.
Reusable: пригодится для регрессий.

## 7.2 Подготовка тестового запуска

Переключи `HEB_ROOT` (через временный env-override, не в
`project.config`!) на `<repo>/examples/smoke`:

```
HEB_ROOT="$(pwd)/examples/smoke" python src/main.py --no-bot --once
```

Флаги:

- `--no-bot` — без Telegram (опц., для smoke не нужен).
- `--once` — обработать одну главу и выйти (если нет такого флага —
  смотри `python src/main.py --help`; в крайнем случае запусти и
  через минуту убей).

## 7.3 Что проверяешь по шагам

1. **Catalog генерится.** В `examples/smoke/articles_catalog.json`
   появился плоский список из 3-5 статей.
2. **Batch-фабрика стартует.** В `examples/smoke/.batch/` лежат
   рабочие папки (по одной на batch), внутри — `prompt.txt` с
   подставленными плейсхолдерами.
3. **Translator-подпроцесс вызывается.** В логах — `claude.exe -p ...`
   запустился, не упал с код-1 моментально. Если нет Claude Code на
   тестовой машине — мокни через `CLAUDE_CMD=echo` env var (или
   аналог, смотри `src/orchestrator.py`).
4. **Результат собирается.** `process_results.py` отрабатывает,
   `Translated/` непустой.
5. **`build_site.py`.** Локально сгенерил `site/index.html`,
   открывается без ошибок в браузере.
6. **(Опц.) Deploy.** Если на стадии 6 был путь (a) и есть тестовый
   репо — push прошёл, GH Pages поднялся. **Не пушь в боевой репо
   оператора с тестовыми данными!** Используй отдельный test-repo или
   ветку.

## 7.4 Типичные грабли

- **Кодировка Windows.** `cp1251` вместо `utf-8` при чтении исходника
  → каракули. Чинится `encoding="utf-8"` в открытии файлов; в нашем
  коде уже сделано, но в свежем loader'е (стадия 2b/c) могло
  потеряться.
- **Пути с пробелами или кириллицей.** В `HEB_ROOT` сходно — лучше
  изначально ASCII.
- **`build_batch.py` не подставил плейсхолдер.** Если добавляла новый
  на стадии 5 — проверь, что dict в `build_batch.py` обновлён.
- **Translator падает с `rate_limit`.** Если используется один и тот
  же Claude-аккаунт для тебя и для translator'а — может всплыть
  лимит. На smoke-прогоне это норм; в продакшене orchestrator
  переживёт сам.

## 7.5 Если упало

Не звоня оператору, попробуй:

- Прочитать tail логов (`logs/orchestrator.log`,
  `examples/smoke/.batch/<batch>/stderr.txt`).
- Сделать минимальную правку, повторить smoke.
- Если падает на той же ошибке после 2-3 итераций — **тогда** покажи
  оператору лог и опиши гипотезу, попроси решение.

## 7.6 Если прошло

Откати временный `HEB_ROOT` (он был оверрайдом, не правкой
`project.config` — это специально). Зафиксируй прогресс:

```json
{
  "current_stage": 8,
  "completed_stages": [1, 2, 3, 4, 5, 6, 7],
  "answers": {
    ...,
    "stage7.smoke_passed": true,
    "stage7.smoke_articles_translated": 5,
    "stage7.smoke_duration_seconds": 380,
    "stage7.smoke_deploy_tested": false
  }
}
```
