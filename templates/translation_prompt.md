# Шаблон промпта для перевода статьи

> **Это пример промпта для корпуса Книги Зоар (комментарий «Перуш
> ха-Сулам»), пара иврит+арамит → русский.** Для другого корпуса
> это **стартовая точка для переделки**, а не готовый шаблон —
> перепиши содержательную часть под свою задачу, сохранив только
> верхнеуровневую структуру (роль, доступ к словарю, правила
> оформления, плейсхолдеры).
>
> Главный агент (оркестратор, см. `ARCHITECTURE.md`) подставляет
> значения в `{{переменные}}` и передаёт результат как `prompt`
> в вызов translator-агента.
>
> **Переменные:**
> - `{{NN}}` — `article_index` из каталога (целое 1-based внутри главы).
> - `{{Chapter}}` — английское имя главы (`chapter`), для логов и фильтров.
> - `{{chapter_ru}}` — русское имя главы с переводом
>   (например `Берешит (В начале)`, `Сифра ди-Цниюта (Книга сокрытия)`).
>   Используется в путях.
> - `{{book}}` — полное название книги
>   (например `Берешит (Бытие)`, `Дварим (Второзаконие)`).
> - `{{sulam_section}}` — имя JSON-файла источника
>   (`Source/Sulam_on_Zohar/{{sulam_section}}.json`).
> - `{{chapter_dir}}` — директория главы:
>   `Translated/{{book}}/{{chapter_ru}}`.
> - `{{start}}`, `{{end}}` — диапазон параграфов Сулам (целые, 1-based).
> - `{{he_title}}` — название статьи на иврите.

---

```
Ты переводишь одну статью комментария «Перуш ха-Сулам» на книгу Зоар.

## Статья
- Номер: {{NN}}
- Книга: {{book}}
- Глава: {{chapter_ru}}
- Название статьи: {{he_title}}
- Параграфы Сулам: {{start}}–{{end}}
- Рабочая директория (HEB_ROOT): {{HEB_ROOT}}
- Инструменты переводчика (corpus_tools): {{CORPUS_TOOLS}}
- Источник: Source/Sulam_on_Zohar/{{sulam_section}}.json
- Выходной файл: {{chapter_dir}}/{{NN:03d}}.md
- Лог-файл: {{chapter_dir}}/log_{{NN:03d}}.txt

## Логирование

В начале:
```bash
cd {{HEB_ROOT}} && echo "[$(date +%H:%M:%S)] START article {{NN}} (pars {{start}}-{{end}})" > "{{chapter_dir}}/log_{{NN:03d}}.txt"
```

В конце:
```bash
cd {{HEB_ROOT}} && echo "[$(date +%H:%M:%S)] FINISH article {{NN}}" >> "{{chapter_dir}}/log_{{NN:03d}}.txt"
```

> ВАЖНО: пути содержат пробелы и круглые скобки — всегда оборачивай их
> в двойные кавычки в bash.
{{resume_block}}
## Пошаговая инструкция

### Шаг 1. Прочитать правила оформления
Прочитай `{{REPO_ROOT}}/templates/formatting_rules.md` — там все правила форматирования
(нумерация, заголовок, выделение цитат, «Пояснение.», аббревиатуры,
названия букв, ссылки на Танах). Это источник истины — следуй ему точно.

### Шаг 2. Получить словарные правила
```bash
cd {{HEB_ROOT}} && python {{CORPUS_TOOLS}}/glossary_tool.py lookup \
  --paragraphs Source/Sulam_on_Zohar/{{sulam_section}}.json \
  --range {{start}} {{end}} -c
```
Используй выданные правила как контекст перевода.

### Шаг 3. Прочитать исходный текст
```python
import json, sys
sys.stdout.reconfigure(encoding='utf-8')
with open('Source/Sulam_on_Zohar/{{sulam_section}}.json','r',encoding='utf-8') as f:
    data = json.load(f)
for i in range({{start}}-1, {{end}}):
    print(f'=== {i+1} ===')
    p = data['he'][i]
    if isinstance(p, list):
        for item in p:
            print(item)
    else:
        print(p)
    print()
```

### Шаг 4. Перевести и записать файл

Выходной файл: `{{chapter_dir}}/{{NN:03d}}.md`.

Чанкование — по объёму исходного текста, а не по количеству параграфов.
Параметр: **бюджет одного чанка = {{chunk_budget_chars}} символов
исходного (ивритского) текста**.

**Алгоритм разбиения на чанки:**

1. На Шаге 3 ты прочитал исходник. Для каждого параграфа Сулам в
   диапазоне `{{start}}..{{end}}` знаешь длину текста в символах
   (`len(text)` для строки или `sum(len(s) for s in parts)` если параграф
   — список строк).
2. Если суммарная длина всех параграфов статьи ≤ {{chunk_budget_chars}}
   → один чанк (один Write, заголовок + все параграфы).
3. Иначе — идёшь по параграфам по порядку, накапливая чанк:
   - Начинаешь новый чанк с очередного непереведённого параграфа.
   - Добавляешь следующие параграфы в чанк, пока
     `сумма_символов_чанка + следующий_параграф ≤ {{chunk_budget_chars}}`.
     Когда добавление следующего параграфа превысит бюджет — закрываешь
     текущий чанк (записываешь его) и начинаешь новый с этого параграфа.
   - **Исключение: если один параграф длиннее {{chunk_budget_chars}}** —
     он сам себе чанк (целиком). Параграфы между чанками НЕ режутся.
4. **Первый чанк — Write** (заголовок + параграфы первого чанка).
   **Каждый следующий чанк — Bash heredoc append** (см. правила ниже).
   Заголовок дублировать НЕЛЬЗЯ.

**Правила Bash heredoc append (для всех чанков 2+):**

Используй именно quoted heredoc `<< 'EOF'` с одинарными кавычками —
он запрещает раскрытие `$переменных` и обратных кавычек, контент идёт
литерально. Шаблон:

```bash
cat >> "{{chapter_dir}}/{{NN:03d}}.md" << 'EOF'

34) **жирный фрагмент** перевод параграфа…

35) **жирный фрагмент** перевод следующего параграфа…

EOF
```

КРИТИЧНО — пробелы и переводы строк:
- Между параграфами **внутри одного чанка**: одна пустая строка
  (между концом текста параграфа N и началом `N+1)` стоит `\n\n`).
  Это совпадает с тем, как Write пишет первый чанк.
- **Heredoc-body должен начинаться с пустой строки** (сразу после
  `<< 'EOF'` — пустая строка, потом `N) текст`). Предыдущий чанк
  уже заканчивается `\n`; пустая строка в начале heredoc даёт ровно
  одну пустую строку-разделитель между последним параграфом
  предыдущего чанка и первым нового — как и внутри чанка.
- **Heredoc должен заканчиваться `\n` после последнего параграфа**
  перед строкой `EOF` (т.е. между текстом последнего параграфа и
  `EOF` стоит одна пустая строка).
- Никаких CRLF. UTF-8 + LF.
- Путь в двойных кавычках (пробелы и круглые скобки в
  `Translated/Берешит (Бытие)/…`).

Не используй `wc -l` / `tail` для поиска «конца файла» — `>>` всегда
пишет в конец, ничего знать о текущем содержимом не нужно.

**После каждого Bash heredoc append** — проверка нумерации:

```bash
grep -c '^[0-9]\+)' "{{chapter_dir}}/{{NN:03d}}.md"
```

Число совпадений должно равняться количеству параграфов, которые
должны быть в файле к этому моменту. Если меньше или больше — НЕ
переходи к Шагу 5, НЕ ставь done.flag; разберись, где промах.

**Общие правила для всех трёх веток:**
- Каждый записанный чанк должен заканчиваться полностью переведённым
  параграфом и переводом строки (`\n`) — частичный параграф «в середине»
  ломает резюмирование при hit-limit.
- Нумерация параграфов в файле сквозная от `{{start}}` до `{{end}}`,
  без пропусков и дубликатов.
- После последнего чанка проверь, что в файле ровно
  `{{end}} - {{start}} + 1` параграфов (regex `^(\d+)\)`), и только
  тогда переходи к Шагу 5.
- Файл перезаписать, если он существует. ИСКЛЮЧЕНИЕ: если выше в этом
  промпте есть раздел `## ВНИМАНИЕ: РЕЖИМ ДОПЕРЕВОДА (resumable)` или
  `## ВНИМАНИЕ: ФАЙЛ УЖЕ ПОЛНЫЙ (resumable)` — файл частично/полностью
  заполнен предыдущим запуском, перезаписывать НЕЛЬЗЯ, действуй по
  инструкциям из этого раздела.

### Шаг 5. Подтвердить успешное завершение

**Только если** Шаг 4 прошёл без ошибок (файл записан, regex `^(\d+)\)`
дал ровно `{{end}} - {{start}} + 1` совпадений) — поставить маркер
успеха:

```bash
cd {{HEB_ROOT}} && touch ".batch/done_{{NN:03d}}_{{Chapter}}.flag"
```

**Если** что-то пошло не так (не успел записать файл, regex дал меньше
совпадений, упал на любом из шагов) — **НЕ** ставить маркер. Отсутствие
маркера = сигнал маркеру `mark_article_done.py`, что статья не
завершена; внешний слой решит, что с этим делать (повторить, пометить
failed, или прервать батч по hit-limit).
